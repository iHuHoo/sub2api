## Migration and rollback

New migration 242_drop_platform_check_constraints.sql drops only the platform CHECK constraints on user_platform_quotas and composite_model_routes. It does not delete rows or change quota amounts. Registered-platform validation remains in domain/service/handler, Ent schema and direct quota repository write paths. Monitor-provider constraints remain unchanged.

The application now accepts Command Code and Cline records. Rolling back the binary does not remove those records or restore the CHECK constraints; assess new-platform accounts, quotas and routes before downgrading. Re-adding old CHECK constraints requires first handling platform values the older application does not support. Never automatically restore an old database over newer writes.
