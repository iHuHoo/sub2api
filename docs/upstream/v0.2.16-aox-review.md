The shared creation form hides Vertex API-key authentication from suppliers because their existing credential allowlist and backend accept only Service Account JSON; administrators retain the new authentication option. A regression test covers this boundary.

New service tests use the existing package-level Gin test-mode initialization instead of changing the global mode during test execution. Ent group field offsets were checked against the new i18n field; supplier account and promo fields remain present. Payment overlap preserves Aox processing while localizing group names.

## Migration and rollback

Four new, additive migrations are included:

- 242_group_i18n.sql: groups.i18n JSONB, empty-object default.
- 243_gemini_cached_contents.sql: cached-content bindings and indexes.
- 244_gemini_cached_contents_channel_usage.sql: cache channel billing metadata.
- 245_gemini_cached_contents_mutation_lease.sql: pending-mutation lease fields and index.

Existing migration files are unchanged. Numeric prefixes overlap existing migration names, but the runner orders and records full filenames and checks their checksums; do not rename already-applied files.

This upgrade is not migration-free. Additive schema alone is not a complete rollback guarantee: explicit caches can create upstream resources with storage charges and pending renewal/recovery work that the older application cannot manage. Before any production rollout, verify backup/restore and define cache cleanup, billing reconciliation and downgrade handling. Never restore an old database over newer writes automatically. Production remains on .23; this source synchronization changes no deployment state.
