## Aox compatibility review

- The Aox payment, CNY conversion, affiliate rebate, subscription promo-code, build-type, and managed-update implementation files were not modified by v0.1.185.
- Pricing and billing changed substantially: long-context pricing is now catalog-driven, pricing JSON patches are supported through `pricing.override_file`, account statistics use the shared billing pipeline, and DeepSeek time pricing is applied consistently.
- Existing Aox payment fulfillment keeps subscription affiliate rebates based on the order's discounted USD `Amount` (`o.Amount`), excluding gateway fees and gateway-currency display values; the upstream token-cost refactor does not enter that order-fulfillment path.
- Existing subscription promo-code reservation, settlement, release, refund, and non-stacking paths remain unchanged.
- Operator-supplied pricing catalogs and `pricing.override_file` patches must include the relevant long-context ladder fields when that pricing is required. v0.1.185 intentionally removes the legacy automatic multiplier fallback, so missing ladder fields keep base pricing instead of synthesizing the old threshold policy.
- `backend/cmd/server/VERSION` is `0.1.184` at the official tag. This is expected because release builds inject their tag version; Aox builds inject the independent Aox version and `BUILD_TYPE=aox`.
