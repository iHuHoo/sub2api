5. 核对目标镜像/版本与迁移：只新增 246，旧 checksum 不变，索引有效，新增列初始 NULL，业务数据无异常。不得重命名迁移、修改 checksum、删除触发器或数据库约束。

## 5. 验收、观察与停止条件

- 公共 health/login/models 为 200/200/401；匿名管理员/诊断接口仍 401。管理员登录及 capability 原始响应 enabled=true/schema_version=1；只读分组、账号、供应商及代理页面正常，供应商看不到分配代理的地址/用户名/密码。
- 已授权范围内验证诊断 quick、最近报告、取消日志降级；诊断禁用的 503 不应再生成 ERROR 堆栈。禁用态验证优先隔离环境，不为测试擅改生产开关。
- 新供应商分配行为先在隔离环境完成验收；生产真实分配/修改账号绑定需要列明对象后另授权，不能顺手拿真实代理做测试。开始真实分配时重新确认第 6 节回退限制。
- 真实网关测试仅在明确 key、模型、费用上限后执行；没有授权则标为待验，不能拿公共 health 替代推理验收。
- 功能验收后观察至少 30 分钟，每 45–60 秒采样容器健康/重启、CPU/内存、网关错误/延迟、日志与迁移异常。Nginx UTC 与应用 +08 统一后关联；流式 HTTP 状态与上游错误分别统计，不直接相加。
- 已知账号限流、支付 #54 缺参、登出响应头过大、Luna 分层尾延迟作为明确基线；不能把新增同类错误无限豁免。认证/归属绕过、凭据泄露、非预期迁移、持续不健康、新增重启、明显新增网关故障或超出中断上限：停止扩量，按事先授予的回退权限执行。

## 6. 回退与新功能使用边界

默认选择：**初次部署及验收期间保持零供应商分配；回退到 .24 时保留迁移 246 的 schema/触发器，接受其校验限制，不自动清空分配或删约束。**

回退前只读计数所有非 NULL assigned_supplier_user_id（包含软删除记录），并检查绑定账号、备用引用以及归属关系。为零且状态与预演相符时，恢复本次备份中 .24 基础 Compose，校验 config，然后只重建 sub2api；核验健康、公开入口、登录、诊断能力及业务。无 schema 降级，不恢复旧 dump 覆盖新业务数据。246 的同归属检查仍然生效，.24 不理解新增约束时可能显示数据库错误，不能承诺所有旧编辑操作都兼容。

如果已产生分配数据：不得继续把换镜像称为“无条件回退”。默认保留数据和约束，停止分配/解绑/备用/直连等管理写操作；.24 不提供新分配管理能力，旧供应商可见性与调度语义未在此状态验证。优先维持 .25 并定位修复。若必须紧急换回 .24，须在授权中明确接受这些功能限制，并有可执行的管理写入冻结措施；无法落实则停止自动回退并升级报告。

**不把“清空分配”作为默认回退操作**：清空可能被账号/备用引用约束拒绝，也可能造成供应商失去代理可见性和使用权。需要清理时先在隔离库复现当前关系、形成逐对象解绑/重绑与业务影响清单，再单独授权；不得批量 UPDATE NULL、disable trigger 或手删 migration 记录绕过校验。
